Changed (#1434): the `fsl 5` syntax edition is published. A document headed `fsl 5` (or `fsl 4`) is read in that edition by `check`, `verify`, `migrate`, `lint`, `fmt`, every other command, the language server and the browser Worker without any opt-in. A document without an edition header is still read as `fsl 4`, and its `check` verdict is unchanged. The unstable gate is removed: `FSLC_UNSTABLE` is no longer read, and the Worker request has no `unstable` field (an old client's `"unstable"` value of any type is ignored as an unknown field). `--edition 4` and `--edition 5` are accepted beside `current` and `next` (`5` is `next`; outputs still spell the edition `current` / `next`), and `fmt --lang` / `--names`, `explain --names` / `--lowering` and `lint --strict-names` are accepted without the gate and are listed in `cli-contract.json`, the help text and the CLI reference page.

Behavior that changes for a document without a header: `lint --edition next` (or `5`) reports `missing_edition_header` (severity `info`) and exits 1 where it exited 0, and `migrate`, whose default edition is `next`, plans inserting `fsl 5` before the first significant line and inserts it with `--write`. A document that takes no edition header, such as `agent`, and a `refinement` document, which is not a standalone check target, are not offered one. Use `--edition current` to keep the former result. A document headed `fsl 5` or `fsl 4` that was refused as the unknown declaration `fsl` without the gate is now read in its edition.

The verify cache key changes: it no longer has an `unstable` field, and it gains an `edition_request` field (the edition number) only when `--edition` is given explicitly. A `verify` result cached before this change under the gate, or with an explicit `--edition`, therefore misses the cache once and is recomputed; a result cached without either is unaffected.

Type-boundary sweep (`fslc check` over every `.fsl` under `specs/`, `examples/` and `rust/fslc/tests/fixtures/`, 651 forms, plus 486 inline fixtures of the rewritten or removed tests), base `49332169e` with and without `FSLC_UNSTABLE=fsl5` against this change: the `ok`-to-`error` set is empty. The `error`-to-`ok` set against the base without the gate is the 17 corpus forms and 16 inline fixtures headed `fsl 4`/`fsl 5`; against the base with the gate, every output is identical.
