`fslc lint` now warns with `shared_requirement_id` where a current-edition `requirements` document gives one requirement ID two owners: a second `requirement` with the ID of an earlier one, or an `acceptance` and a `requirement` sharing an ID. `check` still accepts these documents, and the ledger keeps one row for the ID. The warning is located at the second owner's ID, names the earlier owner, has taxonomy `ambiguous_intent` and is not machine-applicable.
