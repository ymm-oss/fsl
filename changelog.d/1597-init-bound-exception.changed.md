Changed (#1597): Remove the BMC/induction exception that prioritized a step-0 type-bound violation when init both assigned an out-of-type value and evaluated an undefined operation. For example, `n: 0..1` with `init { n = 5 t = 1 / 0 }` now returns exit 2 / `error` / `semantics` with the located init division-by-zero message, rather than exit 1 / `violated` / `type_bound` for `_bounds_n`. A defined out-of-type assignment alone still returns the step-0 type-bound violation.
