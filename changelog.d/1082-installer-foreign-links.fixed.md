Fixed (#1082): `install.sh` no longer takes a skill link it did not create. It used to move anything at `~/.claude/skills/<name>` aside to `.pre-native-v3` and link its own payload in its place. `mise skills sync --global` writes that same directory, so a link mise placed was moved aside and left pointing at nothing mise knew about. Such a link is now reported and left alone. A link whose target no longer exists is still replaced, and a real directory is still backed up as before. A link into an earlier installation is still migrated, whether it points into a pre-native `~/.fsl` (a git clone, or the copy without `.git` that a ZIP download placed there) or into the `current` payload of a data directory that `FSL_DATA_DIR` or `XDG_DATA_HOME` no longer names.
