Changed (#1818): The edition header reads `fsl MAJOR[.MINOR]`. `fsl 5.0` is read as `fsl 5` (and `fsl 4.0` as `fsl 4`); before, it was not a header and the document failed as an `fsl 4` one. A first line that starts like a header but is not exactly one is now refused as `unsupported_edition` instead of being read as a header-less document that then failed with `FSL-DIALECT-UNKNOWN` or `FSL-PARSE`: a malformed or extra number (`fsl 5.`, `fsl 5.01`, `fsl 5.x`, `fsl 5.1.0`), another minor (`fsl 4.1`, `fsl 6.0`, `fsl 5.1` and up), anything after the number (`fsl 5 next`, `fsl 5 spec S {}`), and a trailing `//` or `/* */` comment on the header line (`fsl 5 // note`). For these only `diagnostic_code` and the message change; `kind` stays `parse` and the exit stays 2. The message quotes at most one line of the header, cut after 32 characters. `fsl 5x` is unchanged. This is groundwork for the next minor of `fsl 5`, which is read only behind an unadvertised development gate and adds nothing yet; the `--edition` values, `fsl_edition`, `migrate`'s default `fsl 5` header and the options in the verify cache key of every published run are unchanged.
