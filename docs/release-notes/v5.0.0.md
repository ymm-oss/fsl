# FSL 5.0.0

This summary is for people upgrading `fslc` from 4.12. Each item below names
the issue or pull request whose changelog fragment records it.

## Headline

- **FSL 5 is published.** A document whose first significant line is `fsl 5`
  is read in the FSL 5 edition by every command, the language server and the
  browser Worker, with no opt-in (#1434, PR #1711). `fslc` 4.12.0 refused that
  line as the unknown declaration `fsl`.
- **The opt-in gate is gone.** Pre-release builds of `main` read FSL 5 only
  when `FSLC_UNSTABLE` was set; 5.0.0 no longer reads the variable, and the
  Worker request has no `unstable` field. `fslc` 4.12.0 never had this gate, so
  it matters only if you ran a pre-release build.
- **A headerless document is still FSL 4.** You do not have to migrate.
  However, 5.0.0 refuses some forms that 4.12 accepted, in headerless documents
  as well. Read "Breaking changes" before you upgrade a CI gate.

## Before you upgrade

1. Run the 5.0.0 `fslc check` on every `.fsl` file you own and compare the
   result with 4.12. A refusal is `"result": "error"` with exit 2 and a
   located message; each one has a repair in the upgrade guide.
2. Search scripts and CI for the JSON values, kinds and exit codes listed
   under "CLI, JSON and exit codes" below.
3. Keep 4.12 binaries away from approval records that 5.0.0 writes (#1421).

The step-by-step guide is
[Upgrading fslc from 4.12 to 5.0](https://github.com/ymm-oss/fsl/blob/v5.0.0/docs/manual/LANGUAGE.md#upgrading-fslc-4-12-to-5-0)
([日本語](https://github.com/ymm-oss/fsl/blob/v5.0.0/docs/manual/LANGUAGE.ja.md#upgrading-fslc-4-12-to-5-0)).

## Breaking changes

### Forms that `check` accepted and now refuses

`check`, every `verify` engine and the commands that load a model now refuse
these forms with exit 2. Where a pull request measured the change, the count
of `ok`→`error` forms it recorded is given. Items marked *FSL 5 only* involve
next-edition constructs and cannot occur in a document 4.12 accepted.

- **Range bounds the symbolic engines cannot execute** (#1480, PR #1681):
  dependent, state-reading, `let`-reading or overflowing bounds, negative
  `within` deadlines, typed binders over the builtin `Int` or a Struct, and
  `enum`/`type`/`struct Bool` (`Bool` is now a reserved type name). The PR
  recorded 649 `ok`→`error` forms out of 20,179, none under `specs/` or
  `examples/`.
- **Quantifier and init forms no engine runs** (#1463, PR #1516): 110
  accepted-to-error forms (1 corpus, 109 inline).
- **Init reads before assignment**: reads of an init root before it is fully
  assigned (#1451, PR #1557; 38 inline `ok`→`error` occurrences), and reads in
  an init `forall` of roots the same `forall` writes (#1518, PR #1525).
- **Type checks that used to run only in `verify`**: relation endpoint types
  (#1458, PR #1529), operand kinds and method signatures (#1459, PR #1533),
  relation values with different endpoint bounds (#1522, PR #1635; 10 inline
  removals), container carriers that must match (#1472 and #1627, PR #1647;
  #1679, PR #1689; #1683, PR #1697).
- **Trace and unary operand typing** (#1439, PR #1484; 59 inline removals,
  0 corpus): an ill-typed acceptance `expect` (such as `c != 1` on an enum
  `c`), or an ill-typed FSL 5 scenario `then` (*FSL 5 only*); a step argument
  that is ill-typed inside an acceptance, a forbidden, or an FSL 5 scenario;
  and `not` on a non-Bool or unary minus on a non-Int anywhere in a model
  expression, even in an unselected branch or behind a short-circuited
  `and`/`or`.
- **Names**: a declared name may not contain `__` (#1256, PR #1386), and
  goal, policy, requirement, scenario, forbidden and decision IDs and glossary
  aliases may not either, in both editions (#1602 and #1603, PR #1639).
- **Scoping**: definition calls that capture a caller's names (#1450, PR #1534)
  and `leadsTo` binders that do so (#1528, PR #1618); local bindings named like
  a `const` (#1515, PR #1623); pattern variables used outside their
  continuation (#1547, PR #1610) or reused after a match (#1573, PR #1642).
- **Repeated declarations**: repeated formals or inputs (#1680, PR #1684),
  struct-literal fields (#1685, PR #1690, every position and edition),
  `instances`/`values`/`kpi` declarations (#1686, PR #1691), struct fields
  (#1692, PR #1696), a second `implements` (#1694, PR #1695) and a repeated
  `domain` declaration that loses a copy (#1700, PR #1701).
- **Empty declarations**: an enum with no members, a `dbsystem` without
  columns and an `ai_component` without tools (#1546, PR #1570); AI projects
  with undeclared tools or unknown hard-contract rules (#1545, PRs #1601 and
  #1609).
- **Compose**: synchronized statements that write component state through
  physical names such as `alias__x` (#1334, PR #1527), synchronized arguments
  that read additional-item `let` bindings (#1442, PR #1527), and root
  synchronized arguments typed against their formals (#1517, PR #1677).
- **Requirements**: automatic mappings now compare actors on both sides
  (#1441, PR #1461) and use requirement actions' own actors (#1456, PR #1470);
  unsatisfiable `rule` guards that reuse a field name as an `is` pattern
  (#1552, PR #1564); `is some(name)` patterns that collide with an entity field
  or relation role (#1561, PR #1660; 27 inline removals); legacy transition
  guards that apply `stage(c)` to a binder whose type has no process (#1569,
  PR #1576).
- **Database layer**: an unknown `check compatibility` rule name now fails
  lowering, so `kernel`, `fmt`, `lint` and `migrate` exit 2 where they exited 0
  (#1473, PR #1491).
- **Causal**: `period.valid_until` and `--as-of` must be real `YYYY-MM-DD`
  dates (#1422, PR #1672).
- *FSL 5 only*: `__` in relation roles, resources and measures (#1600,
  PR #1605); repeated step inputs (#1682, PR #1688); repeated actors and
  requirement-ID owners (#1705, PR #1706); a compose child headed `fsl 5` that
  uses a colon quantifier (#1452, PR #1636; 6 inline occurrences); and the
  four next-edition migration forms (enum union, string metadata, colon
  quantifier, inline maps), which `check` already refused in an `fsl 5`
  document and which `analyze`, `conformance`, `explain`, `html`, `kernel`,
  `ledger`, `mutate`, `scenarios`, `sweep`, `testgen` and `typestate` now
  refuse too (#1449, PR #1538). 4.12 refused every `fsl 5` document and child,
  so none of these can break a 4.12 run.

### `fslc refine`

- Incomplete init roots are refused instead of filled with silent defaults
  (#1521, PR #1588).
- In `preserve progress`, a pattern name that matches a free implementation
  name, or a mapping pattern name reused by a sibling, is a located type error
  at `respond`; a run that reported `refines` with exit 0 now exits 2 (#1595,
  PR #1638).
- Conflicting same-named type definitions are refused at the refinement
  declaration; `refinement_failed` with exit 1 becomes `error`/`type` with
  exit 2 (#1599, PR #1651).
- With per-element maps, a free abstract whole-map read in a pulled progress
  property is a type error (#1613, PR #1661).

### CLI, JSON and exit codes

- **Arguments are checked against the CLI contract** (#1446, PR #1465):
  options a command does not own are usage errors on `explain`, `typestate`,
  `mutate`, `testgen`, `html`, `ledger`, `scenarios` and `version` (also
  #1341); several `io`/`semantics` errors become `kind: "usage"`; three-dot
  `--git` ranges are refused; `ai compare` no longer accepts `--` as a value.
- **`kind` changes**: an unreadable input is `kind: "io"`, exit 2, with the
  message `<path>: <error>` on the routes #1709 lists (#1170); the routes listed
  in #1446 report `usage`; `fslc refine` and governance preservations report
  `result: "impl_violated"` where they said `violated` (#1315, PR #1365).
- **Public names**: outputs spell generated and component names as
  `submit.b1` and `acct.Inv` instead of `submit__b1` and `acct__Inv` (#1256,
  #1255, #1284, PR #1386).
- **Approval exit codes**: when `approval create` or `approval check` stops
  because the run that renders the artifact failed, it exits with that run's
  code instead of 2: 1 for a scenarios or HTML verification failure, and 3 if
  that run fails internally. A reviewed artifact that does not match a fresh
  rendering is still exit 2, `kind: "semantics"`, as in 4.12. `ledger --approval`
  reports `result: "error"` naming the record (#1418, PR #1668).
- **Approval records**: 4.12 wrote v1 to v4 (unsigned v1 or v3, signed v2 or
  v4, depending on the kind). New records are unsigned v5 or signed v6 with a
  `path_base` relative to the Git root. Older binaries reject them as
  unsupported schemas. Paths outside the Git root are refused, and
  `document generate --approval` on these records needs Git (#1421, PR #1676).
  New records store a per-kind renderer version such as
  `fslc-ledger-renderer/1.0.0` in `target.generator_version` instead of the
  `fslc` version, so an `fslc` upgrade alone no longer reports
  `renderer_changed`. A 4.x record keeps its bare `4.12.0`-style value. For that
  value the renderer comparison is skipped, so `renderer_changed` is not
  reported, and the record stays `approved` only while every digest matches,
  including the artifact digest against a 5.0 rendering.
- **Approvals whose artifact renders differently need re-approval**: where 5.0
  renders a ledger, HTML or scenarios artifact differently from 4.12, a 4.12
  record of it reports `drifted` with `rendering_changed`, exit 0, while the
  spec digest still matches. Ledger changes include the new legacy-form
  warnings (#251) listed as findings, Markdown escaping, an
  `## inline implements` section for a spec that implements another, reworded
  finding classes, and the assurance wording (#1429). A record whose artifact
  renders the same stays `approved`. Over the 4.12 records that could be
  created for this repository's `examples/` and `specs/`, 61 of 86 ledger, 37
  of 44 HTML and 11 of 45 scenarios records drifted; 14 records of specs that 5.0 refuses or
  whose acceptance or forbidden checks fail end in an exit-2 `error` (#1418).
  Review the new rendering and approve it again.
- **AI dataset paths**: a relative `dataset.source` in an AI declaration is
  resolved from the declaring file's directory, not from the directory `fslc`
  runs in. A path written relative to the repository root stops resolving;
  rewrite it relative to the declaring file, or pass `--records` (#1421,
  PR #1676).
- **Output files** are written atomically; a final symlink, a non-regular
  destination (`-o /dev/null`, `/dev/stdout`, `/dev/fd/63`) and a non-writable
  parent directory are refused with exit 2 (#1419, PR #1671).
- **Edition defaults**: on a headerless document, `lint --edition next` (or
  `5`) reports `missing_edition_header` and exits 1, and a plain `migrate`
  plans the `fsl 5` header and the process-form conversion, so it can exit 1
  with `migrate_manual_required` (#1434). Pass `--edition current` to keep the
  4.12 behaviour.
- **Verify cache**: the cache key hashes the `fslc` version, so the first run
  after the upgrade recomputes every cached result once.
- **Rust library API**: `SymbolicValue::Collection.entries` changes from
  `Vec<(Vec<T>, T)>` to `Vec<(Vec<SymbolicValue<T>>, T)>`; CLI and Kernel JSON
  are unaffected (#1467).
- **Agent Skills**: the layer skills in `skills/` are replaced by FSL 5
  versions that write `fsl 5` files (#1437, PR #1714). The `fsl` skill keeps
  its FSL 4 and kernel guidance. `skills-next/` was never part of a release.

### Verdict corrections

These are fixes, not removals, but a run that passed can now fail, or a
script that matches on the old output can break:

- `verify --engine induction --property P` checks every implicit bound its
  step assumes (#1598, PR #1619).
- An undefined init operation now takes precedence over a step-0 bound
  violation: `n: 0..1` with `init { n = 5 t = 1 / 0 }` gives exit 2
  `error`/`semantics` instead of exit 1 `violated`/`type_bound` (#1597,
  PR #1625).
- `refine` fails closed on pulled-model safety violations (#1599), and
  acceptance and forbidden consumers fail closed when the requirement-trace
  gate refuses (#1242, #1243, PR #1388).
- `ledger` and `html` no longer show unbounded or unknown evidence as bounded
  coverage (#1429, PR #1721), and nonconformant implementation logs add red
  findings (#1548, PR #1567).
- Concrete init failure messages append ` in init at L:C` (#1543, PR #1608),
  and symbolic binder init failures name the concrete failure instead of
  `undefined evaluation` (#1607, PR #1643).

## Deprecated

The current edition now warns on three FSL 4 forms (#251, PR #1538). Verdicts and exit codes are unchanged; under `--edition next`
and in an `fsl 5` document they are `unsupported_in_edition` errors.

| Warning | Form |
|---|---|
| `legacy_string_metadata` | string metadata on a declaration |
| `legacy_quantifier_colon` | `forall x in D: body` instead of a braced body |
| `inline_action_maps` | action mappings written inline |

`fslc migrate --edition 5` rewrites them where its `machine_applicable` flag
says it can.

## Migration

- To keep FSL 4: change nothing in the source, fix any refusal from the list
  above, and update scripts for the CLI changes. The guide
  [Upgrading fslc from 4.12 to 5.0](https://github.com/ymm-oss/fsl/blob/v5.0.0/docs/manual/LANGUAGE.md#upgrading-fslc-4-12-to-5-0)
  gives the command and finding for each item.
- To adopt FSL 5: follow
  [FSL 4 to FSL 5 migration](https://github.com/ymm-oss/fsl/blob/v5.0.0/docs/manual/LANGUAGE.md#fsl4-to-fsl5-migration),
  starting with `fslc lint <file> --edition 5` and a dry-run
  `fslc migrate <file> --edition 5`.

## New features

- The FSL 5 requirements surface: entities, lifecycles, events, rules,
  decision tables, glossaries with Japanese keywords, relations, resources,
  projections, goals, policies and scenarios (#1437, PR #1714).
- `fslc migrate --edition 5` converts a requirements `process` into entity,
  event and rule declarations and checks that the kernel is unchanged
  (#1390).
- `fmt --lang ja|en` and `--names alias|canonical`, `explain --names` and
  `--lowering`, and `lint --strict-names` (#1434).
- `--edition` takes `4` and `5` as well as `current` and `next` (#1715).
- `html --no-timing` for byte-stable reports (#1344, PR #1460).
- `testgen` and `domain testgen` publish `--allow-unwired` (#1446).
- `lint` warns with `shared_requirement_id` when two FSL 4 requirements
  declarations own one ID (#1705, PR #1708).
- Signed v6 approval records bind the path context (#1421).
