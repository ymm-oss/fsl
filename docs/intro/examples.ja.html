実例ギャラリー

リポジトリには完成した実例がexamples/配下に17ディレクトリ、specs/に単独スペックがあります。このページはその案内図です——このマニュアルは実例そのものを複製しません。リンク先はGitHub上のソースです。

検証目標で選ぶ

確立したいことに合う実例を選ぶ

ギャラリーの各ファイルは expected-command と expected-result をコメントで宣言しています。まず目標を合わせ、ソースを開きます — ネイティブ Rust fslc の JSON が主張が成立したかを返します。

見るべき証拠

保証クラスに合ったフィールドを読む

有界安全性

result、completeness:"bounded"、checked_to_depth、violated 時の trace。無限深さの証明ではありません。

無制限証明

result:"proved"、completeness:"unbounded"、エンジン induction または explicit closure:true。書いた性質に限定されます。

詳細化

refines と refinement_failed、マッピング証人、stutter 注記。検査したマッピングの層整合 — システム全体の証明ではありません。

実装観測

testgen はハーネスを生成し、それを実行するか replay を実ログに当てると conformant、failed_at_event、アダプタ投影が得られます。観測されたトレースのみ — 将来の全経路ではありません。

終了コードは docs/LANGUAGE.md とネイティブ rust/fslc/src/outcome.rs に従います — エラー・終了コード を参照。

旗艦例

3層を貫く一本のドメイン

e2e/

コンサルタント・PM・エンジニアが同じ経費精算ドメインを異なる粒度で書き、business ⊒ requirements ⊒ design ⊒ implementationとしてFSLが繋ぐ旗艦例。

layers/

DESIGN-layers.mdの最終形。returnドメインを3ダイアレクトで書き、詳細化チェーンで繋ぐ。

bank/

FSLを一切知らない素のPython実装(bank.py)と、replay/testgenで実装適合を繋ぐ例。

refinement_chain/

層チェーンを通した伝播（business ⊒ requirements ⊒ design …）を確認する例。

境界を明示した正しさの連鎖

方針から実装観測まで

経費精算の例では、各引き渡し先を辿れます。各リンクは万能な証明ではなく、何を示す証拠かを示します。

方針と業務フロー

1_business.fslはコンサルタントのTo-Be統制と目標を表します。

プロダクト要件

2_requirements.fslは受入れ条件と承認境界の要件を担います。

設計と詳細化

3_design.fslは実装に近い支払ステップをモデル化します。

3_refines_2.fslは設計を要件へ対応付けます。

実装の観測

expense.pyはFSLから独立した素の実装です。

test_conformance.pyはAdapterを通して実装を動かします。

検証への橋

testgenは実装適合ハーネスを生成します。

replayは対応付けた完全な観測状態を比較します。

対応付けとハーネスは指定された乖離を検出できます。replayは観測済みトレースの証拠であり、将来の全挙動の証明ではありません。
