What evidence to inspect

Read the fields that match the assurance class

Bounded safety

result, completeness:"bounded", checked_to_depth, counterexample trace when violated. Does not prove infinite depth.

Unbounded proof

result:"proved", completeness:"unbounded", engine induction or explicit closure:true. Still scoped to the written properties.

Refinement

refines vs refinement_failed, witness mapping, stutter notes. Establishes layer alignment for the checked mapping — not full system proof.

Implementation observation

testgen emits a pytest harness whose assertions pass or fail per generated case. replay on a real log is what yields conformant / failed_at_event and the adapter projection. Either way: observed traces only — not all future behaviors.

Exit codes follow docs/LANGUAGE.md via native rust/fslc/src/outcome.rs — see Errors & Exit Codes.

Flagship examples

One domain, all three layers

e2e/

The flagship example: a consultant, a PM, and an engineer write the same expense-reimbursement domain at different granularities, connected as business ⊒ requirements ⊒ design ⊒ implementation.

layers/

The final form of DESIGN-layers.md. The return domain is written in three dialects and chained by refinement.

bank/

Wires a plain Python implementation (bank.py) with no knowledge of FSL to implementation-conformance checking via replay/testgen.

refinement_chain/

Confirms propagation through a layer chain (business ⊒ requirements ⊒ design …).

One bounded correctness chain

From policy to implementation observations

The expense example makes each hand-off navigable; each link names the evidence it provides, not a universal claim.

Policy and business flow

1_business.fsl states the consultant's To-Be controls and goals.

Product requirements

2_requirements.fsl carries acceptance and approval-boundary requirements.

Design and refinement

3_design.fsl models the implementation-facing payment steps.

3_refines_2.fsl maps that design back to the requirements.

Implementation observation

expense.py is a plain implementation, independent of FSL.

test_conformance.py drives it through an Adapter.

Verification bridges

testgen generates an implementation-conformance harness.

replay compares mapped complete observed state.

The mapping and harness can detect stated drift. Replay is observed-trace evidence, not a proof of all future behavior.
